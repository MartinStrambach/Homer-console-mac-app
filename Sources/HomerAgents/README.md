# HomerAgents

Agents and Schedules, an agent's page, the Run sheet, an agent's graphs, New Agent, and an agent's editor with its debug runs.

## Design notes

- **Agents and Schedules** (`HomerAgentsReducer`, one reducer for both) poll `GET /api/v1/agents` every 30 s while shown. The console keeps the list 5 min and refetches on the `/stream/agents` reload event; the poll stands in for that stream, as the process list's does for the status stream, and keeps the schedules' next and last runs current after a cron fires. Run, Edit, New Agent and Reload are offered by the user's grants (`HomerAgentPermissions.swift`, `can(action, agentName?)` from `use-can.ts`); unlike the console, Run needs a `run` grant and New Agent an `edit` grant on some pattern, since the server refuses anyone else. The agent's page, New Agent and the editor are native (below), and its workflow graph is also a sheet over the cards. The instance tells the reducer which of the two pages is on screen (`shown(.agents)`/`shown(.schedules)` — `HomerChildPage` keeps them apart, so moving between them hides one and shows the other, restarting the list's poll) A schedule's Run (Homer 1.31, `POST /agents/{name}/cron-run`, admins only) fires the agent as its cron would, after the console's confirmation, whose wording matters: the call answers 204 even when a preflight (cost cap, cooldown, lock, parallel-run cap) starts nothing, and it returns no process id, so the new run is not opened — the list is refetched and the run shows up as the schedule's "Last run" (`lastRunProcessId`). A non-admin gets the 404 of an unknown agent, so the error names both causes
- **An agent's page** (`HomerAgentDetailReducer`, from `agents/[name]/page.tsx`) shows in place of the Agents or Schedules page that opened it (`openedFrom`), with Back (⌘[) to it; the other page keeps its own content meanwhile. Its agent is the list's — the console's `useAgent` finds it in the agents list too — so the list's 30 s poll keeps it current, and an agent the list drops reads as "Agent not found". Its run history (`/status/all?agentName=`) is polled every 5 s, like the process list, exactly while its page is on screen, and grows with "Load More" rather than the console's Previous/Next, as the process list does. The console stacks the parameters, the workflow graph card and the history on one page; here they are one section at a time (Runs, Parameters, Workflow Graph), so the run `Table` and a large graph each fill the page and scroll by themselves — a `Table` cannot size itself inside a scroll view. The graphs are read the first time their section is shown (the server inspects the modules on every call), and again on its Refresh or the header's Refresh while it is shown. The header adds the cron line (next run counting down, last run opening its run), which the console's page leaves to its badge. The history's columns are the process list's minus Agent, which every row would repeat, with the tags in a column of their own; Kill (asked first) and Retry (opening the new run) are the page's own, against the same grants. Run and Edit go back to the Agents reducer (its Run sheet; the editor), which is why both pages carry the Run and graph sheets (`HomerAgentSheets`). The page is plain optional state with `ifLet`, not `@Presents`: a presented child's effects are cancelled by navigation ID, which nothing outside it can name, and the instance replaces the whole Agents state when it signs out — the poll would go on with no page. So its long effects carry plain IDs (and the graph reducer's load its own), and the Agents reducer cancels them (`HomerAgentDetailReducer.cancelEffects`) on Back, when another agent is opened, and on `hidden` with no page left; `hidden` with the page still there stops only its poll
- **The Run sheet** (`HomerRunAgentReducer`) checks inputs as `lib/utils/validation.ts` does; typed inputs get only the required check, as there. It never sends an empty value: the console sends `""` for empty body and header inputs, which overrides the input's `default`. Query values are percent-encoded including `+`, which `URLComponents` would leave for the server to read as a space. The new run opens only after the sheet's `onDismiss` (`processToOpen` / `runSheetDismissed`): the run's page replaces the Agents or Schedules page the sheet hangs from, which would take the sheet down mid-way
- **An agent's graphs** (`HomerAgentWorkflowGraphReducer`, the console's `workflow-graph-card.tsx`): `GET /api/v1/agents/{name}/langgraph` gives one entry per LangGraph command, a `topology` or an `error` (`busy` when too many inspections run); `200 []` means none. The server runs `homer_langgraph inspect` in a subprocess per call, and the agent list says nothing of which agents have one, so it is asked only when the sheet opens (card button or context menu) and on Refresh, never polled. Shown as structure only — no run, so no tints. The sheet is resizable: a flexible frame alone left its window fixed, `.presentationSizing(.fitted)` makes it resizable from the content's minimum, opening at the ideal size (checked 2026-10-08)
- **New Agent** (`HomerNewAgentReducer`, `new-agent-dialog.tsx`) is a sheet over the Agents page: the name is checked as the console's `validateAgentName` checks it (letters, digits, `-`, `_`) before `POST /api/v1/agents {name}`, which makes the agent's directory with a minimal `agent.yaml` and loads it. A 409 reads as the console's "already exists", other refusals (400) in the server's words. The new agent opens in its editor, as the console navigates there, and the list is read again so the editor finds the agent — until then its debug panel has no commands
- **An agent's editor** (`HomerAgentEditorReducer`, from `agents/[name]/edit/page.tsx`) shows in place of the page that opened it — over the agent's page when its Edit opened it, whose run poll stops until the editor goes (Back, ⌘[, returns to it). Plain optional state with `ifLet` and plain cancellation IDs, for the agent's page's reasons. The console's three panes at its widths: the files (`GET /agents/{name}/files`, flat, directories first; the definition is never offered for deletion), the open file, and the Debug panel for a `debug` grant (`canDebug` — only `role: admin` implies it). It opens `agent.yaml`, else `agent.json`. "Unsaved" is the text differing from what was last read or saved, not "typed since", so undoing back clears it; opening another file or Back with changes asks first (the console asks only on a file switch), and the header's Refresh re-reads the open file only when it has none. Save is ⌘S; a definition the server's schema refuses is a 422 `{msg, errors}`, thrown as `HomerAPIError.invalid` and listed under the header. A save, create or delete reloads the agent on the server, so the agents list is refetched (`filesChanged`). New File writes an empty file and opens it as a tap would
- **The text** (`HomerCodeEditor`) is an `NSTextView` on TextKit 1 standing in for Monaco: monospaced 13 pt scaled, unwrapped, smart quotes and every other substitution off, Tab = two spaces, a new line keeps the indent, ⌘F's find bar. Line numbers are a gutter view beside the scroll view (`HomerCodeEditorContainer`) walking the layout manager — not the scroll view's `NSRulerView`, which sits in the clip view's left content inset that the text view's scrolling to the caret ignores, so the text opened a ruler's width short of its left edge; colors are the layout manager's temporary attributes (`HomerSyntaxHighlighter`, a few regexes per language from Monaco's `languageFor`), which change neither the text nor its undo, re-applied on every edit and skipped past 200 000 characters. Monaco's JSON-schema hover and completion for the definition are not reproduced — the server's check on save is what reports
- **Debug runs** (`HomerAgentDebugReducer`, `debug-command-panel.tsx`; the sheet `HomerAgentDebugRunReducer`, `debug-run-dialog.tsx`): `POST /agents/{name}/debug {commandIndex, env, queryParams}` starts one command as a real run (locks, parallel-run slots and `cooldown.minInterval`, but no cost cap); its refusals are told in the server's words. The sheet starts with a row per declared input (any source, as `getAgentInputs`) and shows the input's env name and transformer under a row that names one; the rows a command last ran with are kept per command for the sheet and Recall, for the editor's lifetime. The latest run's stdout and stderr follow the log stream `HomerCore` shares with the process page (`HomerAPI.logEvents`, resumed from the last byte rather than the console's from-zero-and-dedupe); a 404 means the command has not started writing yet and is waited for without counting as a failure. The tails stop when the Agents/Schedules page goes off screen and pick up where they were when one comes back

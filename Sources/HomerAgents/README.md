# HomerAgents

Agents and Schedules, an agent's page, the Run sheet, and an agent's graphs.

## Design notes

- **Agents and Schedules** (`HomerAgentsReducer`, one reducer for both) poll `GET /api/v1/agents` every 30 s while shown. The console keeps the list 5 min and refetches on the `/stream/agents` reload event; the poll stands in for that stream, as the process list's does for the status stream, and keeps the schedules' next and last runs current after a cron fires. Run, Edit, New Agent and Reload are offered by the user's grants (`HomerAgentPermissions.swift`, `can(action, agentName?)` from `use-can.ts`); unlike the console, Run needs a `run` grant and New Agent an `edit` grant on some pattern, since the server refuses anyone else. The file editor, debug runs and "New agent" open in the web console; the agent's page is native (below), and its workflow graph is also a sheet over the cards. The instance tells the reducer which of the two pages is on screen (`shown(.agents)`/`shown(.schedules)` — `HomerChildPage` keeps them apart, so moving between them hides one and shows the other, restarting the list's poll) A schedule's Run (Homer 1.31, `POST /agents/{name}/cron-run`, admins only) fires the agent as its cron would, after the console's confirmation, whose wording matters: the call answers 204 even when a preflight (cost cap, cooldown, lock, parallel-run cap) starts nothing, and it returns no process id, so the new run is not opened — the list is refetched and the run shows up as the schedule's "Last run" (`lastRunProcessId`). A non-admin gets the 404 of an unknown agent, so the error names both causes
- **An agent's page** (`HomerAgentDetailReducer`, from `agents/[name]/page.tsx`) shows in place of the Agents or Schedules page that opened it (`openedFrom`), with Back (⌘[) to it; the other page keeps its own content meanwhile. Its agent is the list's — the console's `useAgent` finds it in the agents list too — so the list's 30 s poll keeps it current, and an agent the list drops reads as "Agent not found". Its run history (`/status/all?agentName=`) is polled every 5 s, like the process list, exactly while its page is on screen, and grows with "Load More" rather than the console's Previous/Next, as the process list does. The console stacks the parameters, the workflow graph card and the history on one page; here they are one section at a time (Runs, Parameters, Workflow Graph), so the run `Table` and a large graph each fill the page and scroll by themselves — a `Table` cannot size itself inside a scroll view. The graphs are read the first time their section is shown (the server inspects the modules on every call), and again on its Refresh or the header's Refresh while it is shown. The header adds the cron line (next run counting down, last run opening its run), which the console's page leaves to its badge. The history's columns are the process list's minus Agent, which every row would repeat, with the tags in a column of their own; Kill (asked first) and Retry (opening the new run) are the page's own, against the same grants. Run and Edit go back to the Agents reducer (its Run sheet; the web editor), which is why both pages carry the Run and graph sheets (`HomerAgentSheets`). The page is plain optional state with `ifLet`, not `@Presents`: a presented child's effects are cancelled by navigation ID, which nothing outside it can name, and the instance replaces the whole Agents state when it signs out — the poll would go on with no page. So its long effects carry plain IDs (and the graph reducer's load its own), and the Agents reducer cancels them (`HomerAgentDetailReducer.cancelEffects`) on Back, when another agent is opened, and on `hidden` with no page left; `hidden` with the page still there stops only its poll
- **The Run sheet** (`HomerRunAgentReducer`) checks inputs as `lib/utils/validation.ts` does; typed inputs get only the required check, as there. It never sends an empty value: the console sends `""` for empty body and header inputs, which overrides the input's `default`. Query values are percent-encoded including `+`, which `URLComponents` would leave for the server to read as a space. The new run opens only after the sheet's `onDismiss` (`processToOpen` / `runSheetDismissed`): the run's page is a sheet too and cannot come up while the Run sheet is still going away
- **An agent's graphs** (`HomerAgentWorkflowGraphReducer`, the console's `workflow-graph-card.tsx`): `GET /api/v1/agents/{name}/langgraph` gives one entry per LangGraph command, a `topology` or an `error` (`busy` when too many inspections run); `200 []` means none. The server runs `homer_langgraph inspect` in a subprocess per call, and the agent list says nothing of which agents have one, so it is asked only when the sheet opens (card button or context menu) and on Refresh, never polled. Shown as structure only — no run, so no tints. The sheet is resizable: a flexible frame alone left its window fixed, `.presentationSizing(.fitted)` makes it resizable from the content's minimum, opening at the ideal size (checked 2026-10-08)

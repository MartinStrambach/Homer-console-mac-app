# HomerCosts

The Costs page (admins only).

## Design notes

- **Costs** (`HomerCostsReducer`, admins only) runs four loops, so a month or tag key change restarts only one: the rolling-window snapshot every 5 s (`useCosts`' `refetchInterval`), and the month's and all-time ledgers every 30 s — the console only marks those stale after 30 s and re-reads them on mount or window focus, which a page left open never gets. `monthlyLoaded` carries the month it asked for and is dropped once another is picked. With no month picked the request has no `month` and the server answers with the current UTC month, so the page moves to the next month by itself, with no date logic in the app. While a picked month loads, the previous one stays on screen dimmed (the console's `keepPreviousData`). Usage bars follow `CostUsageBar`: green, yellow from 80 % of the cap, red at it; percentages round half up like `toFixed(0)`. The per-agent table lists agents that have spent or have a cap, so a capped agent with no spend shows at $0
- **Cost by tag** (`cost-by-tag-card.tsx`): `GET /api/v1/costs/by-tag/{key}` sums the spend per value of one of the tag keys the server's config tracks (`costTrackedTagKeys`, which only the snapshot names — so the card, and its loop, wait for the snapshot and are left out when it names none). The shown key is derived as the console derives it: the one picked while the server still tracks it, else the first (`shownTagKey`), so a config reload that drops the picked key falls back without being told. Each snapshot re-points the loop (`syncTagPolling`), which re-reads the key every 30 s, the console's `staleTime`; an answer for a key no longer read is dropped, and the previous key stays on screen dimmed while the next loads, as the month does. A key the server no longer tracks is a 400 in the server's words. The rows are the ledgers' (`HomerCostRow`), biggest first, with the console's note when the server summed only the newest 10,000 runs carrying the tag (`truncated`)
- **The page's layout.** Stat tiles head it: the last minute against its cap, the last day (the per-agent spends summed), the month shown and all time. The per-agent table lists the agents nearest their cap first, then the uncapped ones by spend (`byNearestCap`) — the console sorts by name; what needs a look comes first. The global bar ticks 80 %, where it turns yellow. The month's and all-time ledgers list the biggest spender first, each row with its share of the total as a bar, and sit side by side from 900 pt of content width; the cost by tag spans the width under them

# HomerProcessDetail

A run's page: status, executions, command output, artifacts, Claude transcript.

## Design notes

- **The process page** (`HomerProcessDetailReducer`, from `processes/[id]/page.tsx`) is a sheet of the instance (`processDetail`), opened by `processTapped` from every page — the other pages ask through `HomerPageDelegate.openProcess`. It polls `GET /api/v1/status/{id}` every 5 s (the console refetches on its status stream instead) and drops an answer for a run no longer shown. A retry, a resume, a sub run's link or "Parent #id" shows the other run in the same sheet and pushes the current one on `backStack` (Back, ⌘[) — the console navigates. The run's questions are the instance's (`runQuestions`, every status), answered through it (`HomerQuestionCard` with the instance store); when the run's `openQuestions` count moves, the page tells the instance (`.questionsChanged`) to re-read them rather than wait out its 30 s poll. The sheet has a fixed ideal size and a plain stack: a height that followed the executions opening would make the sheet re-measure itself (“Sheets have a fixed ideal size” in the [root README](../../README.md#design-notes)). Switching instance or signing out closes it
- **Command output** (`HomerProcessOutputReducer`, from `view-artifact-dialog.tsx`): `GET /api/v1/artifacts` once, then — while `X-File-Complete` is false — the log stream `GET /api/v1/stream/processes/{id}/logs?cmd=&stream=` with `Last-Event-ID` set to the bytes already read, so nothing is fetched twice (the console streams from byte 0 and swaps buffers). The server sends `log.chunk` with the new end offset as the event id and `{content}` as data, then `log.end`; a dropped connection resumes from the last offset with backoff. A chunk at or below the held offset is dropped. A running command's file 404s until its first byte, so for the live command a 404 means "wait for it". `HomerAPI.events` parses `text/event-stream` itself (`URLSession.bytes`, split on `\n`; `AsyncLineSequence` drops the blank lines that end an event). Appends happen in place on the state — copying the output out of the dictionary first would copy the whole log per chunk
- A Claude command's stdout is NDJSON (`--output-format stream-json`); `HomerClaudeTranscript` reads it as messages and tool calls (`claude-artifact-view.tsx`): Claude only if a `system` event carries `model` (hook events come first and do not), turns counted by distinct message id, tool results matched by `tool_use_id`, a trailing line kept until its newline arrives. It is parsed off the main actor for the first read and appended to per chunk. Shown in a `List` (rows recycle; a lazy stack would drive the sheet's size); raw text in an `NSTextView` (`HomerLogTextView`), which appends the new bytes instead of setting megabytes again and follows the end only while scrolled to it. The console's JSON tree mode is left out
- Downloads (an execution's output files, or any file from the Artifacts sheet, `GET /api/v1/artifacts/list`) go to `~/Downloads` under the file's name, numbered like a browser's when taken, and are shown in Finder — the app is not sandboxed. Artifact paths: an execution's `stdOut`/`stdErr` are absolute server paths, cut to the file name for the API (`toArtifactApiPath`); listed paths are relative and kept
